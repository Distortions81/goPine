# 0.3.20 candidate

After the verified transfer, the user reported entering the pairing code but
never proceeding, with **No saved phone** in INFO. Physical pairing remains
unresolved. Boot/KEEP were not separately volunteered. The follow-up diagnostic
build is documented in [0.3.21](0.3.21.md); no new fix is claimed from that report.

Installed 0.3.19 still failed pairing: Phone slept quickly after waking it and
the passkey/iPhone entry prompt disappeared shortly after appearing.

The custom cooperative port deferred host callbacks out of drawing and input
waits, but failed to return those waits when raw HCI/ATT/SMP events reached the
host queue. Its idle deadline prevented WFE while work was queued, yet the input
loop could spin until a display refresh, up to five seconds away while awake
and potentially much longer asleep. InfiniTime's FreeRTOS NPL event queues wake
their task when events are inserted. The pinned reference is
`6c119eb52206b580b556b41633dddc1e1b66a8da`, including
`src/libs/mynewt-nimble/porting/npl/freertos/src/npl_os_freertos.c` and
`src/systemtask/SystemTask.cpp`.

The port now makes HasUpdate true for queued host events and due host timers.
Wait returns immediately; the shallow main loop runs the callbacks. Drawing,
flash access and HCI semaphore waits still pump only the controller, preserving
the earlier protections against callback nesting. The check preserves the IRQ
mask and does not add a polling timer, queue or buffer. Busy gating prevents
stale work after radio shutdown from keeping the watch awake.

Waking the Phone/INFO screen and returning from INFO now restart the two-minute
setup visibility window. Previously a sleep cleared the window, and a subsequent
wake did not renew it. The code overlay and settings-save deferral remain.

The reference's `nimble_port_freertos.c` runs its controller task at priority 2
and host at priority 1. `ble_ll_conn_event_end` schedules the next connection
event in controller-task context. goPine previously deferred that task work
throughout ECC key generation and ECDH. A fixed service point at each scalar bit
now pumps controller work while host callbacks remain deferred. Firmware and
tests use the same generated pinned TinyCrypt source; two unsigned casts also
remove undefined signed byte shifts in AES key expansion without changing its
math. Vendor files remain unchanged. This is another demonstrated scheduling
gap, but its role in the physical disconnect still needs hardware confirmation.
Removing only controller service from the test's ECC hook reproduces its
pending-controller-work assertion failure; the corrected hook passes.

Comparing InfiniTime's `NimbleController::RestoreBond` exposed a separate
reconnect defect. Its peer-key restore also installs the phone's identity key
in the controller. goPine restored only host memory before startup; controller
reset then erased the resolving list and disabled address resolution. The
pinned host can skip re-enabling resolution when its cached local key is
unchanged. A saved phone using a new private address therefore lost its identity.
The candidate restores peer identity keys and enables resolution after host
sync, before advertising, without rewriting the flash journal. A failed
controller restore retains the saved bond and reports a setup error.

Phone → INFO retains security and disconnect errors with short explanations
and numeric S/D codes. They survive automatic retries and clear on successful
security or Forget Phone; no new flash writes or logging buffer are introduced.

The real GATT client test exposed a configuration error in the ANCS client:
NimBLE defaults client discovery and writes to the BLE central-role setting.
goPine disables that radio role, so ANCS discovery returned `BLE_HS_ENOTSUP`
despite the client code being present. Earlier stubbed GATT tests missed it.
The candidate explicitly enables service-by-UUID discovery, characteristic and
descriptor discovery, and writes. GAP scanning and initiating links remain
disabled; these GATT operations use the existing peripheral connection.

Validation: race-enabled Go tests, vet, eleven C ASan/UBSan primitive suites,
and the real pinned-host sanitizer integration test pass. The latter runs 100
update discovery cycles and ten phone public-key/passkey/update handoffs, now
checking HasUpdate before dispatching raw HCI, ATT and SMP events. Restoring
only the old wake policy in a temporary source copy reproduces the failed wake
assertion. NPL tests cover queued/deferred work, due timers, and IRQ mask
preservation; the production-loop sleep model covers waking Phone again.
The extension completes all 20 passkey rounds, verifies DHKey checks and LTK,
enables encryption and exchanges identity keys. It checks subscriptions created
before pairing are stored under the phone identity rather than its temporary
address, reloads the actual simulated flash journal and restores an authenticated
bonded connection and its subscription. A wrong confirm checks error reporting.
Controller work queued during key calculations runs without recursive host
callbacks. These tests do not complete an actual iOS bond or simulate nRF
interrupts/timing.
The real-host exchange also exercises the early rejected CTS write and trusted
time, weather, music metadata and companion alert writes on both the fresh bond
and restored connection; those writes leave the shared radio active.
The integration test now runs real host startup instead of a startup stub.
It reproduces the old private-address reconnect failure and passes eight
address rotations with the fix, preserving the bond and subscriptions without
additional flash writes. Injected controller-key restore failure also recovers
without deleting the bond. Controller address resolution remains simulated;
this does not establish physical iPhone reconnect behavior.
The new peer ANCS server answers real ATT requests through HCI and the pinned
GATT client, without calling ANCS callbacks or inspecting its state. It verifies
Data Source subscription precedes Notification Source, handles a notification
before the subscription write response, assembles 151-byte attributes from
17-byte fragments, and removes messages. Service Changed indications are
confirmed; disappearance clears the session and a later publish rediscovers it.
Denied notification sharing leaves battery/weather usable, then succeeds on the
bounded retry when permitted. These flows repeat after bonded reconnects.
The test failed before enabling the client operations and passes with them.
Shared synthetic InfiniLink wire fixtures now replace the transport test's
zero-timestamp weather packet, which the Go decoder would reject. The real host
preserves 9/10-byte calendar packets, v0/v1 current weather, a five-day forecast,
music metadata/position/duration and an app alert. It verifies all supported
music control notification bytes and rejects an old connection generation.
The Go controller test uses those same fixtures and verifies automatic clock
application, decoded weather, music state and the inbox on one connection.
These tests verify the two stages separately, not a captured iPhone session.

BLE firmware build and selected-path resource checks pass. MCUboot image:
291,252 bytes. Reserved RAM: 23,156 bytes; heap region: 42,380 bytes; task stack:
8,192 bytes. These are regression budgets, not runtime peak measurements.
The resource gate now includes selected C frames through ECC and nested
controller work: 4,856 bytes plus the unchanged 2,048-byte reserve, below 8,192.
Package: `build/ota/gopine-dfu-0.3.20.zip` (218,087 bytes).
SHA-256: `4aed1febc7350dc9fd2c3611f0ffeebbe3395afe8c4766823d59548da7dd1692`.
The package reader validates the application manifest, image/version and DFU
checksum against the built image.

On 2026-10-10, the watch advertised goPine Update and received the full image
through the TP-Link `hci1` direct uploader. Receiver validation succeeded at
100%; INSTALL and boot/KEEP have not been reported. Log:
`build/ota/upload-0.3.20-20261010-023723-130669.log`. The log spans approximately
6 minutes 19 seconds including connection and validation. No transfer retry is
shown. This measures the 0.3.19 receiver, not the candidate's update performance.
The candidate has not been published. The last user-confirmed installed baseline
is 0.3.19 with boot/KEEP confirmed and pairing failures reported. A stable iPhone
prompt, completed InfiniLink pairing, bonded reconnect, automatic time/weather
and ANCS delivery still need physical validation. The missing wake signal is a
reproduced defect; its role in the physical prompt cancellation is an inference
until a hardware test confirms it.

The same scheduling fix may reduce update latency because ATT requests also
use the host queue. Measure an in-app transfer running the new receiver before
claiming a speedup.
Compression remains out of scope. Optional progress-notification work is parked
while pairing is being repaired; it is not included in this image or clients.
