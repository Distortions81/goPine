This patch fixes a Bluetooth security conflict that can interrupt Linux updates
before firmware transfer begins.

- During the watch's explicit Firmware Update session, automatic Battery Service
  reads can succeed without pairing. In 0.3.15, the battery read required
  encryption while update mode rejected new pairing requests; Linux's automatic
  battery probe could therefore trigger repeated disconnects.
- Normal phone-session battery reads retain the existing encryption requirement.
  Battery notifications and saved-phone pairing behavior are preserved.
- The [browser updater](https://distortions81.github.io/goPineTime/) now downloads
  and validates the latest release automatically. A chosen local ZIP takes
  precedence, and a failed or stalled download leaves manual selection available.
- Recoverable browser timeouts reconnect using the same transfer session and
  acknowledged byte count. Connection and discovery get up to 30 seconds per
  request, retries are bounded by 90 seconds without progress, and stalled native
  Bluetooth requests must close before another transfer starts. Error messages
  identify the stage that failed.

If a watch already running 0.3.15 repeatedly disconnects on Linux, the webpage
cannot change the installed firmware's pairing policy. Use the documented
[recovery update route](https://github.com/Distortions81/goPineTime/blob/main/docs/ota.md#legacy-recovery-update-with-one-command-linux)
to install this patch if the in-app transfer still cannot connect. Tap **KEEP**
after a successful boot. The browser cannot communicate with the recovery clock.

Validation includes browser regression tests, C ASan/UBSan tests of the production
Battery read path, and a full BLE OTA build with enforced memory budgets. The
published artifacts also pass the release workflow's application and host-tool
checks. A real Chrome/Linux transfer, phone pairing and battery notifications on
this patched firmware still require hardware confirmation; this release does not
claim those checks have passed.
