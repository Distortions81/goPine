# 0.3.19 candidate

Phone setup on installed 0.3.18 slept after the normal 15-second inactivity
timeout. InfiniLink could remain Connecting while the watch showed Securing
connection. Clearing an earlier saved bond produced a code and iPhone prompt
briefly, but the user could not finish entering it.

This follow-up fixes two reproduced interruptions:

- Opening Phone with Bluetooth enabled or tapping CONNECT PHONE keeps Phone
  and INFO visible for up to two minutes while waiting or securing. Successful
  authentication ends that screen hold. Normal sleep resumes after the window,
  and the side button still sleeps immediately. The shared radio remains active.
- Saving AUTO CONNECT previously stopped the radio after a two-second delay
  unless a pairing code was already visible. Settings saves now defer throughout
  the setup window and security negotiation, including when the screen sleeps
  or the user leaves Phone. Waiting without a peer only defers saves for the
  bounded setup window. Saving resumes after authentication or Bluetooth Off.

The comparison used the pinned InfiniTime source at
`6c119eb52206b580b556b41633dddc1e1b66a8da`, especially
`NimbleController.cpp`, `SystemTask.cpp`, and `PassKey.cpp`. InfiniTime wakes
the display when showing a pairing key and leaves its BLE connection active
through display sleep. It also permits repeat pairing by deleting the peer's
old bond; goPine currently requires the explicit Forget Phone action instead.
The sources use the same Secure Connections and display-only passkey setup.

Validation: race-enabled Go tests and vet pass. Production-loop tests with a
simulated 15-second inactivity timer cover waiting/securing, bounded sleep,
successful authentication, and manual button sleep. Persistence tests cover
pre-code discovery, security after leaving Phone, delayed saves, and restart
after the save. Restoring the previous sleep/save conditions in a temporary
source copy makes both corresponding regressions fail. The BLE firmware build
and selected-path resource gate pass; reserved RAM remains 23,156 bytes, the
heap region 42,380 bytes, and the task stack 8,192 bytes. These are regression
budgets, not measured runtime peaks.

SHA-256: `be1884213f30830e26bd1f5849beab787d052208058b239a6fbd2c72d9291606`.

This candidate was transferred through goPine's in-app updater, verified by
the watch, and confirmed with INSTALL, successful boot and KEEP on 2026-10-10.
It has not been published. Installed baseline is 0.3.19. A physical InfiniLink pairing, stable passkey prompt,
bonded reconnect, automatic time/weather and ANCS delivery are still required.
The identified interruptions are not yet proven to explain every canceled
iPhone prompt or the earlier hardware crashes.

After boot/KEEP, the user reported that Phone setup still slept quickly and
the code/iPhone prompt disappeared shortly after appearing. Pairing still did
not work. The [0.3.20 follow-up](0.3.20.md) fixes a missing raw-host-event wake
signal and the setup timer after waking Phone; hardware confirmation is pending.
