# 0.3.18 candidate

This local candidate adds iPhone notifications and gives pairing one home under
**Settings → Phone**. The watch booted and accepted KEEP on 2026-10-10 after a
validated recovery transfer. This candidate has not been published. The previous 0.3.17 version
crashed before showing a pairing code on one attempt and did not complete pairing
after code entry on another. The changes below address identified hazards and
missing ANCS support; they do not establish that the on-watch crash is resolved.

The first direct upload attempt on 2026-10-10 sent no firmware: the installed
0.3.17 watch rebooted when the uploader connected, before service discovery
completed. Flashing was paused at the user's request to investigate first.

That investigation reproduced a GATT restart defect in the real pinned host:
the second Bluetooth start freed/reinitialized ATT memory without clearing the
old attribute list or registering the consumed service definitions again. The
second connection lost Battery/service lookup. The port now registers its fixed
service table once and preserves the database across subsequent host starts,
keeping resource counts and handles stable. This
is a reproduced invalid-memory/service-state defect, not evidence of RAM
exhaustion. Confirming that it explains the physical watch reboot still requires
a hardware test.

After boot/KEEP, the user reported that Phone setup slept quickly and InfiniLink
stalled at Connecting while the watch showed Securing connection. INFO showed
Phone pairing saved. After clearing that bond, a pairing code and iPhone prompt
appeared briefly and disappeared before code entry. Pairing remains unvalidated.
The [0.3.19 follow-up](0.3.19.md) addresses two reproduced setup interruptions.

- **One pairing entry:** Settings → Phone → CONNECT PHONE is the only setup
  entry. Weather, Music, Time & Date, and Inbox no longer contain connection
  buttons. They use the existing saved phone connection automatically.
- **iPhone alerts:** the ANCS client discovers the iPhone's service, subscribes to
  Service Changed and its notification/data sources, and requests title/message
  text through Control Point. New notifications enter Inbox; modifications
  preserve their local identity/read state and removals delete the matching
  Apple message. Silent and pre-existing notifications do not buzz.
- **Normal InfiniLink setup:** the candidate requests security when a phone
  connects, without waiting for the app's Battery read. Its ANCS implementation
  targets InfiniLink's default Force ANCS mode. Accept iOS notification-sharing
  permission when prompted. This flow still needs on-device acceptance.
- **Shallower pairing work:** screen rendering and input waits service controller
  timing while deferring host callbacks to the main loop. The host pump also runs
  before larger weather/music packet frames. Passkey injection is deferred until
  its own security callback unwinds, and injection errors close the connection.
- **Safe Bluetooth restarts:** restarting after Phone, settings saves or updater
  handoffs preserves the registered GATT database. The updater also defers full host
  processing to the main loop instead of running it inside its large OTA frame.
- **Bounded notification work:** four queued notification IDs, a 151-byte
  fragmented response, and two 147-byte output records limit C storage. Epochs
  reject callbacks from replaced sessions; disconnect/security failure clears
  Apple identifiers and messages while preserving Android ANS messages. Missing
  or unauthorized services retry at 30-second deadlines at most three times,
  then wait for a service-change indication or reconnect. Malformed/timed-out
  responses stop that ANCS session; vanished notifications can be skipped safely.

Dismiss removes a message from the watch's local Inbox. Remote notification
actions, call answering, and an Apple AMS client for system-wide media control
are not implemented. Apple Music control through InfiniLink remains available.
Weather delivery still depends on the companion's existing foreground/location
refresh policy. See [phone setup and limits](../pairing.md).

Validation passed: race-enabled Go tests, `go vet`, eleven C ASan/UBSan suites,
and a real-host integration suite with a simulated controller. The latter runs
100 update connect/discover/Battery/status/disconnect cycles and 10 interleaved
phone security requests, Secure Connections public-key/passkey exchanges and
update handoffs. It reproduces the old failure on the second host start; it does
not simulate nRF interrupts, complete phone bonding or measure Go runtime stacks.
The integration suite is now included in CI and release validation.
Also passed: 15 resource-checker tests, the 78-object ARM BLE archive, screen rendering checks,
and the full BLE OTA build. Tests cover fragmented/max-size ANCS text, discovery
and subscription order, burst bounds, stale callbacks, vanished IDs, deadlines
including timer wrap, silent/pre-existing alerts, updates/removals, and keeping
pairing out of feature navigation and drawing callbacks.

The rebuilt image is 285,476 bytes. Reserved RAM is 23,156 bytes, the heap region is
42,380 bytes, and the task stack remains 8,192 bytes. Selected Go paths use
3,176 bytes before deeper Bluetooth host work and 3,728 bytes for Apple inbox
processing, with the resource checker reserving another 2 KiB. These are
regression budgets, not measured whole-program peaks.

Offline validation passed for `build/ota/gopine-dfu-0.3.18.zip` (214,055 bytes).
SHA-256: `b933f263acfac64ff2cfe116b9941829e813d100caa33ae0fab9ccdd8454fef5`.
Recovery transfer, receiver validation, boot and KEEP are confirmed. Hardware
